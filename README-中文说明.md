## 一、一句话说明

这是一个**紫微斗数排盘网站**（网页程序），装在你电脑本地，不联网也能排盘。
输入出生年月日和时辰，它画出 12 宫命盘，还能查古籍原文、星曜百科。

它不是普通的「双击就能用的软件」，而是**需要先启动一个本地服务、再用浏览器打开**的网站。
为了方便你，我做好了一个**双击就启动**的快捷脚本（见第二节）。

## 二、怎么打开（最简单）

**方法一（推荐）：双击桌面上的「紫微斗数」图标**（2026-10-30 新增）

- 图标是深蓝底 + 金色命盘圈 + 「紫」字
- 双击 → 弹出一个黑色窗口 → 浏览器自动打开 http://localhost:3000
- 如果服务**已经在运行**，双击只会打开浏览器，不会再启动第二个（不会端口冲突）

**方法二：双击脚本**

1. 打开文件夹 `D:\ziwei-doushu\`（在「我的电脑 → D 盘」里）
2. 双击 **`启动紫微斗数.cmd`**
3. 会出现一个黑色窗口，里面滚动一些英文（正常现象，别关它）
4. 几秒后浏览器会自动打开 → **http://localhost:3000**
5. 用完想关掉：**直接关掉那个黑色窗口**即可

> ⚠️ 黑色窗口 = 网站正在运行。关掉窗口网站就停了，想再开就再双击一次。
> ⚠️ 如果浏览器没自动打开，就手动在地址栏输入 `http://localhost:3000`。
> ℹ️ 桌面快捷方式指向的是 `D:\ziwei-doushu\启动紫微斗数.cmd`；如果移动或删除了那个脚本，快捷方式会失效（图标也会变白）。

快捷入口：`D:\软件\ziwei-doushu`（这是指向真实目录的「联接」，点进去是同一个地方）。

## 六、本地解读数据集（我加的，2026-10-30）

### 为什么加

开源版的解读面板只能调 AI（接口不存在），所以点开宫位看不到文字解读。
上游另外放出了**解读数据集 v4.0**：674,976 张命盘 × 13 维 = **8,774,688 段解读**，
覆盖 1950–2026 每个真实日期 × 12 时辰 × 男女，按倪师《天纪》逐字稿与《紫微斗数全书》逐句校正。
这是**已经生成好的文字**，不需要 AI 就能直接查。

### 我做了什么

| 项目 | 内容 |
|---|---|
| 下载数据 | `year-1960` ~ `year-2026` 共 **67 个年份文件**，134 MB（每个 2 MB 左右） |
| 存放位置 | `D:\ziwei-doushu\data\interp-v4\`（已加入 `.gitignore`，不进版本库） |
| 后端接口 | `app/api/interp/route.ts`：接收年月日时辰性别 → 流式解压当年文件 → 按 key 找到那张盘 |
| 前端页面 | `app/interp/page.tsx`：生辰表单 + 13 个维度切换 + 全文显示 |
| 排盘页入口 | 起盘后左上角多了一个「本地解读（数据集）→」按钮，点了自动带上你的生辰 |

**关键设计**：不把 56.6 GB 解压到硬盘，而是**查询时实时解压那一年**（约 700 MB 文本），
边解压边找目标行，找到就停。所以磁盘只占 134 MB。

### 怎么用

方式一（推荐）：打开 `http://localhost:3000/chart` → 填生辰起盘 → 点「本地解读（数据集）→」

方式二：直接打开 `http://localhost:3000/interp` → 填生辰 → 选维度看

### 速度

| 情况 | 耗时 |
|---|---|
| 目标盘在文件靠前位置 | 0.3 秒 |
| 目标盘在文件中间（最坏情况） | 约 2.3 秒 |
| 同一个盘再查 | 0（内存缓存） |

### ⚠️ 一个必须知道的口径差异

数据集是**按时辰序号直接排盘，没有做真太阳时校正**；而排盘页会按出生地经度校正。

- 大多数人两者一致（除非出生地在偏远经度，或出生时间正好在时辰交界附近）
- 如果不一致，页面会**明确警告**：「填报 X 时，校正后是 Y 时，本页内容对应 X 时那张盘」
- 想查与排盘页完全一致的盘，需要按校正后的时辰手动查（数据集不提供该口径）

### 数据集没有的部分（上游声明）

- 网站按读者当前年龄改写的句子
- 各维度末尾附加的倪师法则段
- AI 解读
- 真太阳时校正

## 七、技术信息（供以后排查）

- 框架：Next.js 16.3.8（Turbopack）+ React 19 + TypeScript + Tailwind CSS
- 依赖：181 个包，已用国内镜像 `registry.npmmirror.com` 安装成功
- 端口：3000（如被占用，Next 会自动换成 3001，请看黑色窗口里的提示）
- 启动命令：`npm run dev` ｜ 自检：`npm run test` ｜ 类型检查：`npm run typecheck`
- **版本管理**：2026-10-30 起本项目是 git 仓库（`D:\ziwei-doushu\.git`），已关联上游
  `https://github.com/Renhuai123/ziwei-doushu`，并配了 `ghfast.top` 加速镜像。
  `node_modules`、`.next`、`data/interp-v4` 已在 `.gitignore` 里，不会进版本库。

### 已知情况（不影响使用）

1. ~~`npm test` 最后一组会失败~~ **已于 2026-10-30 解决**：本机装好了 Git，本项目也建成了 git 仓库
   （`D:\ziwei-doushu\.git`），`git ls-files` 能正常列出 116 个待检查文件。
   现在 **10 组测试全部通过**（耗时约 24 秒），排盘功能本身一直是好的。
2. **黑色窗口里可能出现 `Watchpack Error ... D:\System Volume Information`**：这是扫描 D 盘时碰到
   系统保护目录，属正常噪音，不影响页面。
3. **`esbuild` 的 postinstall 被 npm 安全策略跳过**：只影响 `npm test` 里的 tsx 脚本链，不影响网页。
4. 首次打开某页面会稍慢（要现场编译），之后很快。
5. **本地解读首次查询要 0.3–2.3 秒**（现场解压当年 700 MB 文本找那一行），同一张盘再查是 0 秒。
   依赖 Node 24 内置的 zstd 解压（本机 v24.19 已确认可用）；若以后换到旧版 Node 会失效。
6. **数据集只覆盖 1950–2026**，本机装的是 1960 年起。查 1950–1959 或 2027 年以后会提示没有数据。
